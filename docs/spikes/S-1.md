# S-1: a transparent, non-activating overlay on a Mac

Run on 2 Nov 2026, Apple Silicon Mac, Tauri 2.12, Rust 1.99. The code is in `src-tauri/` (window and commands) and `src/playground/overlay.ts` (the page). It is the same cat as the playground, fed with real window positions.

## What was built

- One transparent, borderless window per display, each exactly over its display, above the Dock (level 21), on every Space. The window on the main display runs the cat and sends its state to the others every frame.
- It starts click-through. A Rust command reads the real cursor position and the primary button state in global points (read only). When the cursor is over the cat, the page turns click-through off, so the cat can catch the mouse. When the cursor leaves, it turns it back on.
- Rust sensors (`src-tauri/src/sensors.rs`): window list, idle seconds, camera and mic flags. See [S-2](S-2.md), [S-3](S-3.md), [S-6](S-6.md).
- A debug line goes to the console every 3 seconds (cat position, platform, intent, window count, click-through, cursor and hit box), so a run can be checked without a screenshot.
- `FELINQUENT_DEMO=1` cycles every 25 seconds: the front window, a window on another display, the Dock. 
- `FELINQUENT_DEBUG=1` draws the red "clicks blocked" box. It is hidden otherwise, demo mode included.
- The overlay uses the local Ollama model when `gemma3:1b` is installed, with the rules brain as the fallback. `FELINQUENT_BRAIN=rules` turns it off.

## What happened

| Check | Result |
|---|---|
| Window exists, transparent, over the whole screen, above the Dock | Yes. Core Graphics lists it at layer 21, 1440 x 900. |
| The cat stands on real windows | Yes. The platform id was a real window id and `y` matched the window's top edge (175). The cat jumped from the Dock up to a window on its own, and walked along the top when the demo sent it. |
| It never takes focus | **Only after a fix.** The first runs made the overlay the frontmost app. See below. After the fix two clean launches left the frontmost app (System Settings) unchanged, checked with `lsappinfo`. |
| Two displays (the second above the main one) | Both windows sit exactly on their displays (`0,0 1440x900` and `0,-1080 1920x1080`, from Core Graphics). The cat walked from the Dock up to the second display's floor, along it, and back. **Not seen by eye**, only in the log. A window on the second display was out of jump range (1022 points up, the limit is 810), so the cat stared at it from the floor, as designed. |
| The model works inside the app | Yes. The page fetched Ollama on localhost and the first decision came back with `source: llm`. |
| Clicks pass through except on the cat | The hit box and cursor positions in the log are consistent, and click-through was seen flipping to off once. **Not tested** with a deliberate click on the cat and a click beside it. |
| Works across Spaces and over fullscreen apps | **Not tested.** The collection behavior is set (all Spaces, stationary, fullscreen auxiliary). |

## Things that bit

1. **Sync Tauri commands deadlocked.** Commands that touch the window (`current_monitor`, `cursor_position`) hang when they run on the main thread. Making them `async` fixed it.
2. **`requestAnimationFrame` stops** in this window. It is transparent and click-through, so WebKit treats it as hidden. The page uses a 16 ms timer instead.
3. **Launching steals focus once.** A new app is activated by macOS at launch. The fix: run as an accessory app (no Dock icon, no menu bar), make the window not focusable, and call `deactivate` for the first 1.6 seconds after launch. This still moves focus briefly at startup, so it needs a typing test (type in another app while the cat launches) before it counts as solved. A real `NSPanel` with the non-activating style would be the cleaner fix if that shows problems.
4. **Window noise.** Browser toolbars show up as separate full-width slivers, and a second display (Universal Control) shows windows at negative `y`. The page keeps only windows at least 100 points tall that sit on this screen.
5. **macOS moves windows below the menu bar.** Placing the second overlay normally put it 30 points too low (it overlapped the main display and missed the top of its own). Setting the `NSWindow` frame directly fixed it.
6. `screencapture` failed ("could not create image from display"), because the terminal has no Screen Recording permission. I did not ask for it, so there is no screenshot of the overlay. The check above is from logs and window listings.

## Not done

- Spaces, fullscreen apps, auto-hidden Dock, mixed display scaling, side-by-side layouts, plugging a display in or out while it runs (displays are read once at launch).
- A look at the cat on screen (screenshot or video).
- A packaged `.app`. This ran as a plain binary built in release mode.

## Result

The shell works and the fallback (a small moving window, or a Swift helper) is **not needed so far**. The first gate asks for no focus stealing and hit-area click-through, and those two are only partly shown. See G1.

## Run it yourself

```bash
npm run build
cd src-tauri && cargo build --release && cd ..
FELINQUENT_DEMO=1 ./src-tauri/target/release/felinquent     # Ctrl+C to stop
```

It draws over your screen, so be ready to stop it.
