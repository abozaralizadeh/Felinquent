# S-4: small-model quality for intents

Run on 2 Nov 2026, Apple Silicon Mac, Ollama 0.34.4, model `gemma3:1b` (806 MB, Q4). 60 repeatable scenarios per run, the model answers with a JSON schema whose `intent` field is an enum of the menu items.

| Seed | Valid | Invalid | Errors | p50 | p95 | Distinct intents | G1 mark |
|---|---|---|---|---|---|---|---|
| 1 | 98.3% | 1 | 0 | 1604 ms | 2692 ms | 7 | pass |
| 2 | 96.7% | 2 | 0 | 1593 ms | 3109 ms | 8 | fail |
| 3 | 98.3% | 1 | 0 | 1988 ms | 3451 ms | 6 | fail |

The original mark is at least 98% valid and p95 under 3000 ms. The relaxed mark is at least 95% valid and p95 under 5000 ms. All three runs meet the proposed mark.

## What it says

- The 1B model is right on the edge. Validity hovers around 97 to 98 percent and p95 sits between 2.7 and 3.5 seconds. One run in three passes. That is not a pass.
- Invalid answers are not a safety problem. The governor re-checks every answer and the rules brain takes over, so an invalid answer costs one wasted call and nothing else.
- Latency is fine for this job. The cat decides every 20 to 60 seconds, so a 2 to 3 second answer is invisible. The p95 mark was set for a snappier feel than the cat needs.
- Only one model was tried. The plan says to compare two or three. That needs more downloads, so it is left for later.

## How to repeat

```bash
ollama pull gemma3:1b
npm run eval -- --brain ollama --n 60 --seed 1
```
